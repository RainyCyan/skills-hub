# Grill: 示例、自我合理化与红旗

正文已含流程与停止条件。此处只放正文不重复的判别材料：一个完整对话示例、常见借口的反驳、红旗清单。

## 示例：两问问出"要的根本不是这个"

```
User: 给我做个 dashboard 看我们的指标

Agent:
HYPOTHESIS: 你想在站会上回答"我们进展如何"，"dashboard"是惯例说法。
CONFIDENCE: ~30% — 缺：给谁看、"指标"指什么、成功长什么样

Q:     "进展如何"是谁在问——你自己、站会上的工程团队、还是往上（经理/高管/董事会）？
GUESS: 站会上的工程团队，因为"我们"通常这么划分。若给高管看，指标和框架会大不一样。

User: 其实是给我自己。我老是记不清哪些实验在跑、早期信号如何。

Agent:
更新读数：根本不是团队 dashboard，是个人实验追踪器。CONFIDENCE: ~60% — 还缺："早期信号"指什么、done 长什么样。

Q:     缺口是你不知道有哪些实验，还是看不到它们的结果在一处？
GUESS: 后者。你有实验清单，但结果散在五个工具里，手动对账让你累了。

User: 其实是前者。我根本没有清单，它们散在不同文档里。
```

两问之后，真实需求不是"dashboard"，是"一份清单"。不同产物、不同范围、不同工作量。dashboard 会是错的。

## 常见自我合理化 → 现实

| 借口 | 现实 |
|---|---|
| "需求够清楚了" | 若现在无法一句话写出用户想要的结果，就不清楚。先跑第 1 步再判断。 |
| "问太多浪费时间" | 4–6 个聚焦问题浪费的时间很小；做错东西浪费的时间巨大，且成本由用户承担。 |
| "边做边搞清楚" | 代码存在后切换成本是现在的 10 倍。实现期的发现就是返工。 |
| "他说'你看着办'，我该自己定" | "你看着办"是委托不是决定。用两个具体选项重问。 |
| "我该给他几个选项挑" | 选项适用于用户已知道要什么、在权衡之间选。他还不知道要什么时，列选项是拓宽搜索；提问才是收窄。 |
| "附上猜测就是在引导他" | 引导正是目的——反应比从零生成快。风险是附和而非引导；靠明显地愿被推翻来对冲。 |
| "聊够了，我懂了" | 测一下：能预测接下来三个问题的反应吗？不能就还没懂。 |
| "用户说 yes 了，完事" | 若 yes 跟在含糊的 restate 或开放式"听起来不错"之后，这个 yes 是空的。具体地 restate 再确认。 |

## 红旗

- 一条消息三个及以上问题：是批处理，不是访谈。
- 问题不附假设：是调查，不是承诺。
- 把"你看着办"当作终态答案接受。
- 用户显式 yes 之前就产出了 spec/plan/任务清单。
- 问题框成"什么是最佳实践"而非"你到底想要什么"。
- 用户给出 sophistication-signaling 答案（"scalable"、"clean"、"modern"）而你未追问就接受。
- 连续三轮置信度不见上升：在问错问题，退一步重构框架。
- 置信度 <70% 却不附原因：用户不知道缺什么就无从帮你。
- 用户确认前就保存 intent 文件（文件本身暗示了未给出的 yes）。
- restate 里省了 "Out of scope"（对非目标的沉默分歧是一半错配）。

## 与其他阶段的关系

- 本 skill 是决策**前**的意图提取；对已起草的 plan/spec 做压力测试属于决策**后**的产物审查，是另一件事。
- 下游消费本 skill 的意图：把需求变体化、把需求写成 spec、再拆成任务，都在拿到显式 yes 之后。
