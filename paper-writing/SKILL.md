# 中文毕业论文写作

把用户已有的研究工作转化为论证完整、证据可追溯、符合学校规范的中文毕业论文。写作不能替代研究本身；资料不足时保留明确缺口，不用流畅文字掩盖证据空白。

## 入口路由

先判断用户当前只需要哪一种模式，只执行该模式及其必要前置步骤：

| 模式 | 典型请求 | 默认产物 |
|---|---|---|
| 项目建模 | “帮我梳理论文”“从头开始写” | 研究简报、缺口清单、推进顺序 |
| 论证与目录 | “设计大纲”“重构章节” | 总论证链、章节职责、节级目录 |
| 章节写作 | “写摘要/绪论/第三章” | 可直接进入论文的正文和待补项 |
| 文献综述 | “整理研究现状”“写综述” | 分类综述、争议/缺口、引用映射 |
| 修改审校 | “润色/降重/改写这段” | 保守改写或带定位的诊断 |
| 证据审计 | “检查论证/引用/结论” | 主张-证据判定和修复动作 |
| 定稿审查 | “全文检查”“提交前过一遍” | 跨章一致性、编号引用、格式风险 |

用户已给定明确范围时直接执行。只有缺失信息会改变事实、论证方向或学校格式时才提问；一次只问当前阻塞项。

## 硬门禁

Always 区分四类内容：

- `已提供`：用户材料中明确存在。
- `已核验`：已从可访问的原始来源、数据或代码中确认。
- `合理推导`：由现有证据推出，但原材料未直接陈述。
- `待补充`：完成正文所需但当前缺失。

Never 编造文献、作者、年份、题名、DOI、页码、政策条款、数据、样本量、访谈、实验过程、统计结果、图表、公式来源或学校格式要求。

Never 把摘要、搜索结果片段、二手转述或参考论文中的表述伪装成已读全文所得结论。仅有摘要时，只能写摘要直接支持的范围。

Never 把研究计划写成已完成工作，也不能把预期结果改写成实验结论。时态必须反映研究状态。

Never 为填满章节而扩大结论。结论的对象、条件、时间、样本和适用边界不得超过证据覆盖范围。

Never 逐句仿写范例论文。范例只用于观察章节功能、信息密度和术语习惯；观点、表述和证据必须来自用户自己的研究与已引用来源。

Never 承诺“通过 AI 检测”或用同义词替换掩盖抄袭。对“降重”请求，重建论证和表达，并保留必要引用。

资料不足但用户要求先出草稿时，使用以下占位符，不得静默补全：

- `[待引文：需要支持的具体主张]`
- `[待数据：指标、样本或时间范围]`
- `[待核验：作者、年份、页码或原文]`
- `[待确认：研究设计或学校要求]`

## 建立事实基线

开始跨章节写作前，从用户材料或工作区中确认以下事实；已有内容不重复询问：

1. 学位层次、学科、学校模板和引用规范。
2. 题目、研究对象、研究问题或假设。
3. 数据、样本、实验、系统、案例或文本材料的真实状态。
4. 方法、对照基线、评价指标和已获得结果。
5. 用户已有目录、术语表、参考文献库及目标文件格式。
6. 本次交付范围、长度和是否直接修改文件。

学校规范未知时，采用中性章节结构并标记格式待确认，不把通用习惯写成学校规定。

任务跨越多个章节或多轮对话时，使用 [assets/thesis-brief.md](assets/thesis-brief.md) 和 [assets/evidence-ledger.md](assets/evidence-ledger.md) 维护单一事实来源。优先更新用户已有的等价文件；不要在 skill 目录中写项目状态。

## 写作状态机

### 1. 固定总论证链

在目录或正文之前，先在内部确认研究可压缩为：

`现实/理论问题 -> 现有研究局限 -> 研究问题或假设 -> 方法与设计 -> 证据 -> 解释 -> 结论 -> 适用边界`

用户要求项目梳理、目录或论证分析时显式输出该链；用户只要正文时不要输出分析过程。链条中任一节点缺失时，指出缺口及其对后文的影响。不要通过新增形容词或“重要意义”补洞。

### 2. 建立主张与证据映射

对核心主张执行 [references/evidence-and-integrity.md](references/evidence-and-integrity.md)。至少确认：

- 该主张需要文献、数据、推导、案例还是设计产物支持。
- 当前证据直接支持、部分支持还是不支持。
- 证据是否覆盖主张的条件与范围。
- 反例、替代解释和研究限制是否被处理。

文献综述必须按问题、方法路线、结论分歧或适用条件组织，不能按作者逐篇罗列。每一组文献都应回答“已知什么、凭什么、仍缺什么、本文接哪一处缺口”。

### 3. 设计章节职责

使用 [references/chapter-contracts.md](references/chapter-contracts.md) 选择当前章节契约。每章只承担一个主问题，并明确：

- 输入：前文已经建立的事实或概念。
- 本章问题：这一章必须回答什么。
- 核心主张：读者读完应接受什么结论。
- 证据：用什么材料使主张成立。
- 输出：给下一章提供什么。

如果两章回答同一问题，合并或重新分工；如果某章没有独立输出，不因篇幅需要保留。

### 4. 起草正文

先写可检验的内容句，再补必要衔接。一个论证单元通常包含“主张、证据、解释、边界”，但不要机械地把每段写成相同模板。

正文必须满足：

- 讨论中的猜测不直接进入正文；先转化为可核验命题。
- 段首提出该段实际问题或判断，不先报告“本节将介绍”。
- 数据后解释其与研究问题的关系，不只复述数值。
- 图表先在正文中被引用，再说明读者应观察的变量和比较。
- 方法选择同时说明适用条件与未选择替代方案的理由。
- 负结果、异常值和不一致证据不得被省略。
- 术语、缩写、符号、时态和研究对象前后一致。

撰写中文正文或审校语言时加载 [references/chinese-academic-writing.md](references/chinese-academic-writing.md)。

### 5. 验证后交付

交付前逐项检查：

1. 论证链是否闭合，章节结论是否回答开头提出的问题。
2. 每个外部事实和他人观点是否有真实来源。
3. 每个结果性判断是否有数据、推导或材料支撑。
4. 是否把相关性写成因果，把局部样本写成普遍结论。
5. 引文是否支持紧邻主张，页码、图表和编号是否可核验。
6. 摘要、正文和结论中的数字、术语、贡献与限制是否一致。
7. 是否仍含占位符、内部讨论、虚构细节或未定义缩写。
8. 是否符合用户指定模板；未知规范是否仍被明确标记。

## 修改既有论文

Before 修改，先识别作者原意、关键事实、引用标记、LaTeX/Markdown/Word 结构和用户要求的修改强度。

仅要求“检查”时，默认先给带位置、问题、影响和修复动作的诊断，不改文件。明确要求“直接改”“润色”或指定文件编辑时，直接修改并保持原作者可辨认的语言习惯。

Only if 原句存在事实错误、逻辑断裂、歧义、冗余、引用错配或明确风格问题才改。不要为了显示工作量替换无问题的同义词。

处理 LaTeX 时保留命令、标签、引用键、数学环境和用户宏；除非用户要求，不改公式语义。修改后检查 `\label`、`\ref`、`\cite` 和环境是否配对。

## 输出契约

用户只要正文时，直接输出正文，不在正文中插入执行过程或自我评价。

存在未解决缺口且用户允许带说明交付时，把交付拆成两个明确区块：

1. `论文正文`：只放可成立的正文与必要占位符。
2. `待补证据`：逐条列出占位符所需材料及补齐后影响。

用户要求“只给正文”时，把待补信息保留为规定占位符，不追加正文外说明。

证据审计使用 `主张 | 所需证据 | 当前证据 | 判定 | 风险 | 修复动作`。判定只能是 `支持`、`部分支持`、`不支持`、`待核验`。

直接编辑文件后，简要报告修改范围、仍未解决的事实缺口和完成的验证，不把这些说明写入论文文件。
